Component review — the widgets before they are used 175 times

Every widget below is drawn from this machine, live, right now. Nothing on this page is sample data. The rules they keep are in the comments of widgets.js; they come from the dataviz skill that docs/gui-goal.md section 4.4 asks this project to follow.

1 · A value against a real limit

The meter is the default form. The track is the fill's own hue, so the state reads across the whole bar; the hairlines on the track are the thresholds the hardware publishes, so the room that is left can be seen without reading a number.

2 · The same values, drawn round

The dataviz skill puts "a single ratio against a limit" on a meter, not on a dial, so a dial is kept for at most one hero value in a view. Both are here so the choice is yours, not mine.

3 · A value with no published scale

109 of the 175 channels on this machine publish no maximum, and only 5 publish a threshold. For those, the widget shows the number and the line and draws no bar, because a scale that is invented is a lie. The old dial in the spike drew Tctl against 0 to 100 °C, and the hardware never said that.

4 · Change over time

The vertical axis keeps a floor and only moves when the data leaves it, so a quarter-degree wobble does not fill the box and the line does not jump while the value stands still. Put the pointer on a chart for the crosshair and the value under it.

5 · What a colour means

One colour for each state, the same everywhere. The colour never travels alone: the validator in the dataviz skill reports that warning, serious and critical are not far enough apart for a colour-blind reader, so each one carries an icon and a word.
